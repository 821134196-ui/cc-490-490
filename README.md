# 公交场站轮椅坡板点检与车辆放行系统

车辆出场前按班次检查轮椅坡板**外观、展开/收回、锁止、车内呼叫按钮**（同时核验固定销与承重标识），
全部合格才可放行；发现故障后车辆进入**无障碍功能停用**或**整车待修**，按线路要求换备用车；
维修完成必须由**驾驶员重新点检**并记录测试结果。

零第三方依赖：Python 3.11 标准库 + SQLite + 原生 HTML/CSS/JS。

## 一条本地启动命令

```bash
./run.sh
# 等价于 python3 -m ramp_system.server --reset --port 8080
```

打开 http://localhost:8080 （不重置已有数据可去掉 `--reset`）。

只生成/查看三个必选样例（卡滞、换车、复检失败）的留痕，不启动 Web：

```bash
python3 -m ramp_system.samples
```

运行测试：

```bash
python3 -m unittest tests.test_core -v
```

## 八个业务看板

1. **线路待发板** —— 按线路、发车时间排列的高密度行；车辆编号旁有坡板状态点（合格/不合格/停用/未检）；近发车时间橙色、超时红色。
2. **车辆点检（驾驶员端）** —— 侧视车辆轮廓 SVG，坡板、铰链、锁止、固定销、承重标识、呼叫按钮均为可点击热点；大字号卡片逐项勾选；展开/收回计时与照片上传。
3. **坡板测试** —— 每次点检/复检的展开、收回耗时、往复次数、结果与说明。
4. **故障停用** —— 七类故障登记（卡滞/固定销缺失/按钮无响应/标识脱落/漏检/延期/误放行），选择「无障碍停用」或「整车待修」。
5. **备用车调配** —— 备用池余量、待换车班次、换车留痕；容量耗尽时按钮禁用且后端拒绝。
6. **维修进度** —— 开工/完工/延期，到期与超时红色提示；进程内线程每 20 秒扫描。
7. **复检** —— 仅驾驶员可提交；结论**图标 + 文字**同时显示（✅ 复检合格—恢复运营 / ❌ 复检不合格—继续停用退回维修）。
8. **放行记录** —— 每张放行单的门控抬杆信号与车辆终端通知信号，另有全程留痕时间线。

## 内置样例（启动即有）

- **坡板卡滞**：12 路 TR-003 / 车 103 展开 60% 卡滞 → 无障碍停用 → 调度换 **备901** 并完成点检放行 → 维修换滑轨 → 复检合格恢复运营。
- **备用车容量**：105（固定销缺失）换备 902、106（承重标识脱落）换备 903，三辆备用车全部占用；102（按钮无响应）再申请换车被 `SPARE_NONE_AVAILABLE` 拒绝并留痕。
- **复检失败**：7 路 TR-002 / 车 102 呼叫按钮无响应 → 整车待修 → 维修更换线束且台架通过 → 驾驶员实车复检按钮仍无响应 → 复检失败、继续待修。
- 另有**司机漏检、误放行、维修延期**的登记/事件留痕。

## 核心业务规则与实现位置

| 规则 | 实现 |
|---|---|
| 同一车辆同一班次仅一份有效点检 | 部分唯一索引 `uq_active_inspection` + `Store.submit_inspection` |
| 四项（实际六项）全合格才放行 | `Store.can_release` |
| 故障 → 停用/待修 → 按线路换车 | `report_fault` / `swap_vehicle` |
| 维修后必须复检，复检不合格回退 | `complete_repair` + `reinspect` |
| 职责分离（驾驶/调度/维修） | `_require_role`，每个写接口强制校验 |
| 放行幂等 + 并发只成一次 | `releases.trip_id UNIQUE` + `BEGIN IMMEDIATE` + 唯一约束竞争回退；门控仅成功路径调用 |
| 八类情形留痕 | `faults` 表 + `events` 时间线（界面「全程留痕」） |
| 发车时限 / 维修超时提醒 | `ReminderThread` 守护线程 + `scan_reminders`，超时自动登记漏检 |
| 车辆终端 / 门控模拟 | `ramp_system/adapters.py`（放行成功才发信号，重复放行不重发） |
| 测试照片本地目录 | `data/photos/`（上传落盘 + `photos.json` 清单） |

## 数据与目录

```
ramp_system/
  store.py      # SQLite schema + 全部业务规则
  adapters.py   # 门控 / 车辆终端 / 照片存储 模拟适配器
  seed.py       # 演示数据与三个必选样例
  samples.py    # 样例留痕导出
  server.py     # HTTP 服务 + 进程内提醒线程
static/         # index.html / styles.css / app.js
tests/test_core.py  # 18 项规则测试
data/ramp.db    # SQLite（班次、车辆状态、点检、故障、维修、放行…）
data/photos/    # 测试照片
```

## 测试覆盖

```
python3 -m unittest tests.test_core -v
```

- 班次唯一：重复点检 409、复检作废旧不合格单后仍只有一份有效；
- 故障阻断：无点检/不合格/停用/待修均阻断，阻断事件留痕；
- 换车容量：备用车逐台占用、耗尽拒绝、已占用车不可二次调配；
- 职责分离：非驾驶员不能点检/复检、非调度员不能换车/放行、非维修不能开工；
- 放行幂等：6 线程两调度员并发，只 1 单成功、门控只开 1 次。
